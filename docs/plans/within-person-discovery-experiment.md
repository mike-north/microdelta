## Question and adoption boundary

Can one declared, Supervision-owned traversal feed immutable frontiers to normal
Resolution requests **within one actual run invocation**, so cold PR A publishes
while page two's actual controlled acquisition is held, and the strict person
summary body remains unstarted? After that page fails, can a separate fresh
process restart at the root, justify current A evidence and retain A's exact
eligible assessment reference?

The owning outcomes are [RUN-003–005](../spec/operations.md#run-003--readiness-is-scoped-to-the-consuming-calculation),
[CMP-1/4/8/9](../spec/composition.md), current source acceptance and
[exact reuse](../spec/execution.md#reuse-002--current-finality-hooks-are-authoritative).
The candidate is the plan's restricted root source-call authority and explicit
request-bound frontier/currentness contract. It preserves ordinary collection
results, captured request populations, member keying, strict-fold readiness,
History publication, operation fencing and Accounting rules.

A pass would support only that selected bounded mechanism and its generated
internal/alpha declaration path. It would not prove the full nested person/report
pipeline, mutable remote-provider consistency, public authoring syntax, generic
pagination, #170 completion, M6/M7, or scale/endurance behavior. The plan's
[full-person integration relationships](within-person-discovery.md#path-from-a-flat-proof-to-the-full-person-workflow)
remain a later child; this flat proof cannot replace them.

## Selected surface to resolve before software

The supervisory owner selected the plan and this charter after architecture and
different-agent design review. A later runtime issue must cite the selected revision
and preserve the following semantic surface; API names and private owner-port
encoding remain engineering choices subject to the usual declaration review.

- One composition declares a fixed person/query traversal, exactly one supplied
  page source, one ordinary frontier collection, one flat PR template and one
  separate strict person fold before graph freeze.
- The page source is reached only through Definition's restricted root-call
  witness and a Resolution-supplied dispatch capability bound to the current run.
  Query/continuation arguments have current tracked evidence. Existing source
  callbacks still return one outcome and have no child/collection mode.
- The declared frontier source receives only the immutable evidence captured for
  its normal request. Resolution checks relationship/invocation association and
  capture eligibility when creating that root-request capture. Owned declared
  children use the existing captured binding during soft drain, without a new
  capture or a producer-live recheck that would revoke it. The source applies
  current policy and publishes an ordinary fresh collection result, not a mutable
  view.
- The producer and consumer requests share one run's stop, operation engine,
  allowance, admission pools and fenced writer. Producer failure selects soft
  stop: no new root requests/captures, independent top-level page/member
  admissions or retries. First attempts of declared children demanded by an
  admitted, executing, untainted/non-pending parent still reach ordinary admission
  policy and retain that parent's captured bindings through drain. Hard stop or
  deadline escalation prohibits further affected child admissions and sends.
  Terminal discovery and publication follow RUN-014's existing rules. No
  application store or publisher participates.
- The flat PR template has current discussion/detail sources and an assessment
  memo whose exact result is A's reusable expensive result. The strict fold
  consumes these declared assessment instances. It is a different body from the
  producer and PR work. Current source policy/consumed inputs determine reuse;
  page position/frontier number does not enter PR identity.

The first runtime task is to map these semantics to actual Definition, Resolution
and Supervision owner ports and ordinary generated imports. If that mapping
exposes a concrete contract conflict or requires materially broader authority,
report it before widening scope. Current API absence is the reason for the
extension, not by itself evidence that the experiment is blocked.

The deterministic service contract supplies a fixed qualifying set and explicit
query/revision/continuation evidence for each invocation. The adapter sees only
its responses and those advertised facts. The checker privately owns the full
fixture manifest; the adapter, currentness hooks and coordinator must not read it.
Different authorized invocations may select different fixed datasets or consumed
content. A single traversal cannot claim fixed consistency after receiving
contradictory revision/identity evidence.

All expensive/provider operations are controlled synthetic operations with body
and actual-send counters. No credentials, paid providers or real GitHub calls
are used. Synthetic usage includes explicit reported and unknown outcomes where
appropriate; a zero provider bill does not justify rewriting unknown usage to
zero. This small fixture measures correctness only, with no O(1), performance,
150,000-subject or production resource claim.

## Evidence and causal witness

Use actual runtime owner APIs through ordinary package imports/generated
declarations, the normal SQLite History path and controlled operations. Do not
substitute a test-only resolver, handcrafted stored result, private population-map
edit, host send or manually copied values for the mechanism under test. The
independent checker may read the resulting History after the worker exits through
normal read-only facilities. Runtime observation hooks and counters must expose
the witness without supplying currentness or changing the schedule.

One authoritative trace records worker PID, live invocation's opaque harness
association, declared traversal/relationship descriptor, request identity,
frontier sequence, source-hook/body/admission/send events, operation attempts,
exact result references, fold readiness/body/publication, producer terminal
outcome, stop/drain/exit and available resource measurements. The invocation
association is created at actual run entry and ends only after its owned tasks
drain; all witness events must occur within that same interval, with the same
run context/operation authority. It is test evidence, not a new persistent public
run identity. The checker verifies that no second run entry occurred in the
primary worker. Equal public `runId` text is insufficient.

The primary causal sequence is deterministic:

1. A fresh store has no candidate for A. Page one actually acquires and validates
   A; the adapter offers open F1. Its consumer request captures F1.
2. Page two enters its actual send and signals `page2-held`. The controlled send
   does not return, throw or release its permit until the harness supplies the
   selected continuation. No response is secretly ready behind a delayed log.
3. While that barrier remains held, the F1 consumer resolves current A sources,
   executes A's assessment once and receives the exact committed reference from
   normal publication. Record the publication acknowledgment and reference.
4. Before releasing page two, assert the same invocation is live, its producer
   is still at `page2-held`, strict summary body count is zero, no strict-summary
   admission/body/publication occurred, and F1's strict outcome is waiting/open.
5. Only those acknowledgments authorize the harness to release page two for the
   selected success/failure. A watchdog expiry never supplies success evidence.

The scheduler may start the page-two send before or after F1 capture, but A's
cold publication must follow the actual hold acknowledgment and precede release.
This proves useful work while a real later acquisition remains pending. A
pending timer, earlier completed page, cumulative snapshots in separate runs,
cross-person overlap or elapsed-time comparison cannot satisfy it.

With page two holding one actual-send permit, the other permit is available to
A's sequential discussion, detail and assessment operations. The primary case
expects exactly one page-one send, one held page-two send, and one each of A's
three controlled operations before release; maximum concurrent sends is two.
Assessment body count is one and summary body count is zero. A one-permit run
may legitimately wait for the held send; classify that capacity limit separately
from a coordinator/lane deadlock under the required two-permit configuration.
No mandatory zero-permit preemption or freeing an actual send is assumed.

### Discriminating admitted-step drain pair

WPD-2/9 must not test cancellation only after A has committed. Reuse the
controlled two-request assessment variant, but declare its second request inside
a fixed child of assessment parent A before graph freeze. With page two actually
held and F1 already captured, admit A and finish request one. Pause A's executing
body **before** it demands that child: the child has not yet been admitted, and A
is untainted, not pending and still executing. This variation crosses the new
captured-binding lifetime without adding a separate scenario matrix. Record its
request counts separately from WPD-1's single-request assessment counts.

1. **Soft drain:** request soft stop, or fail page two through the selected
   soft-stop producer-failure path, at that pause. Resume A so its body demands
   the declared child. The fixture's ordinary admission policy permits this
   child's first attempt within A's drain unit. The child must read/use A's
   still-owned captured F1 member/argument binding, with its association and exact
   frontier evidence visible in the normal trace. It must not require a new root
   request/capture or renewed producer-live authority. Queue the child's first
   controlled send behind the permit/rate barrier, then release that barrier
   without escalating stop. The child sends and completes; A completes and
   publishes under the current fence/commit rule. A fresh independent top-level
   page/member admission, root request/capture and retry are each refused. The
   strict summary stays unstarted. A wrapper that permits draining sends but
   rejects this child admission or prematurely revokes F1 fails the oracle, as
   does a global hard-abort substitute or voluntary cancellation of this positive
   fixture.
2. **Hard/deadline control:** reproduce that admitted-parent state and soft-stop
   child admission through the point where the child's first send is queued.
   Request hard stop or explicit operator-deadline escalation **before** releasing
   the barrier and before A's commit boundary. The child's queued request has
   zero later actual sends and A publishes no partial assessment; further
   affected child admission is prohibited. Record interruption and any already
   possible page-two operation's confirmed cancellation, running or unknown
   remote outcome without converting unknown usage to zero. This pair fixes
   escalation before A's commit; it does not retract any result already committed
   under the existing linearization rule. Owned captured evidence remains held
   until drain/cleanup completes, then its capability is unusable.

The selected soft-stop path has no new default deadline. Finite harness watchdogs
bound this experiment, not the runtime policy: a missed bound is inconclusive,
and any hard/deadline escalation used for cleanup is explicit and separately
recorded. Both sides must drain/release their run-local resources; a timeout or
cooperative cancellation cannot masquerade as proof of prohibited soft sends.

For WPD-6's legitimate overlap, adapter coalescing precedes Definition's existing
whole-snapshot keying; this does not change the duplicate-key contract. Neither
page movement nor same identity alone proves current detail. WPD-8's unchanged
child control and changed consumed facts must be selected from actual tracked
reads, not a hand-maintained cache invalidation list.

## Tests first and independent assessment

Before implementation, the runtime child must write Jest outcome assertions for
WPD-1/2/3/4/9/10 and the relevant negative rows, and tsd assertions for the
selected declaration/authority boundary. The tests must observe the expected
failure on the baseline before implementing the new seams. A compile refusal
for the genuinely absent declared root/frame binding is meaningful type RED;
a runtime test that never reaches the hold or fails because its fixture is
malformed is not meaningful live-handoff RED. Where a missing surface prevents
runtime execution, record that limitation, then demonstrate the behavioral
assertion at the first callable seam before adding its mechanism. Do not
fabricate baseline counts or classify green existing controls as new RED.

Existing ordinary open-snapshot member admission, duplicate keying, strict-fold
readiness, writer fencing, source-call acceptance and restart tests are controls.
Retain their governing checks; use them to isolate regressions without claiming
they already prove page streaming. New assertions must test the new authority,
frame-capture, terminal handoff and same-run scheduling outcomes. Use ordinary
repository check/build/test and declaration/import gates in the runtime child;
no casts, private source aliases, weakened lint, `skipLibCheck`, fake History
publication or broader host authority may make the probe pass.

The main runtime worker records exact commands, baseline RED, selected revision,
controlled inputs, counts, references and terminal/resource results. After that
worker exits, the independent checker opens the durable store and validates A's
published result/reference plus fixture coverage and trace ordering. The recovery
worker then opens the store in a distinct OS process; it receives only durable
store/fixture configuration, never live closures, caches, frame tokens or saved
page continuation. It records current hooks and zero eligible assessment work.
The checker must independently inspect fresh-process evidence, not merely trust
the worker's PASS label. Neither a memory backend nor two contexts in one process
proves restart reuse.

A different agent reviews the actual tests, source changes, generated surface,
traces, references and counterexamples before the supervisor accepts the result.
Design review now validates coherence and scope; it cannot replace this later
mechanism and independent-process review.

## Verdict and next decision

**PASS** requires all selected mandatory outcome rows, exact-reference/currentness
checks, same-invocation witness, declaration boundaries, finite budgets and
independent evidence to agree. Record any bounded controls separately. A pass
permits a supervisor decision on adopting only the demonstrated seam; it is not
automatic runtime adoption, full nested integration or #170 closure.

**REJECT** applies when the selected authority or behavior conflicts with an
owning contract: undeclared sends/topology, hidden mutable currentness, mutated
population/results, false closure, started strict body while open, wrong exact
reuse, reset allowance, escaped stop/drain or stale-fence publication. Return the
concrete trace/source counterexample for supervisory review of a revised bounded
design or reconsideration of B; do not weaken the oracle or select B implicitly.

**INCONCLUSIVE** applies when the witness is missing, a bound expires, required
measurement/source evidence is unavailable, the owner-port mapping cannot be
assessed, or process termination prevents an oracle. It is not a pass, proof of
impossibility or license to expand resources. Record the precise remaining
engineering question and the smallest proposed next experiment for review.

No software, runtime probe, provider call or experimental RED/GREEN/result is
claimed by #297's documentation decision. Ordinary repository checks, tests and
builds validate the revision for delivery; they supply no new live-handoff
evidence. Architecture and different-agent
design review support the bounded selection; final review of the documented
decision and the normal protected PR/Copilot/CI/main integration gates remain
required. Any later execution needs a separately scoped issue and review of its
actual invocation matrix, finite operation allowance, measurement and concrete
launcher bounds within these charter ceilings.
