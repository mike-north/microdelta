## Findings

### 1. Insufficiently tested: abrupt death inside allocation and staging transactions

**Spec.** PUB-004 calls for explicit recovery after death “during allocation or payload persistence” ([execution.md:349–356](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/docs/spec/execution.md#L349-L356)); A-09 says to kill every commit boundary ([acceptance.md:35](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/docs/spec/acceptance.md#L35)).

**Implementation.** Allocation's generation and attempt writes are grouped in one transaction ([index.ts:260–296](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L260-L296)); staging's payload/state write is another ([316–334](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L316-L334)). Both run through an immediate SQLite transaction ([node-sqlite.ts:44](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/harness/node-sqlite.ts#L44)). The candidate boundaries appear atomic by construction.

**Tests.** Current child-process cases kill after allocation or staging has returned (and therefore committed) ([publication.test.ts:138–179](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/publication.test.ts#L138-L179)). The kill-before-commit wrapper is used only around publication ([crash-worker.ts:56–66, 159–175](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/harness/crash-worker.ts#L56-L66)). Generic transaction rollback tests throw an exception, not SIGKILL ([sqlite-capability.test.ts:56–64](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/sqlite-capability.test.ts#L56-L64)).

**Smallest follow-up.** Add file-backed child cases that run the allocation SQL or stage update, then SIGKILL before their transaction callback returns. After fresh reopen, assert allocation has neither a partial attempt nor a consumed generation (the next allocation receives that generation), and staging leaves the attempt allocated with the prior current pointer intact. This is missing crash-boundary coverage, not evidence of a code defect.

### 2. Insufficiently tested: stale-operation rejection preserves the complete successor state

**Spec/model.** `RejectedStaleMutationPreservesDurableState` covers successor holder, expiry, fence, and current pointer ([Publication.tla:167–174](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-7/Publication.tla#L167-L174)); PUB-002 prohibits stale renewal, publication, or release from changing successor authority/current state ([execution.md:332–338](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/docs/spec/execution.md#L332-L338)).

**Implementation.** Each fenced operation reads and checks all three authority facts before writing in the same transaction ([index.ts:463–475](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L463-L475), with call sites cited above). I found no implementation mismatch.

**Tests.** The stale-writer test proves all five stale operations throw but only checks `currentWriter()?.holderId === 'second'` afterward ([publication.test.ts:253–285](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/publication.test.ts#L253-L285)). It does not prove the successor expiry/fence or current pointer stayed unchanged; its scenario starts without a completed current result.

**Smallest follow-up.** Capture the full successor `currentWriter()` lease and `readCurrent()` result before the stale operations, then assert both are byte-for-byte/equality unchanged after all rejects. Seed a completed current result first so stale publish is tested against a nonempty pointer. Also assert the stale attempt state/payload did not change after rejected staging. In a separate minimal case, assert an authorized renewal updates expiry while preserving holder/fence, and an authorized release clears the holder while preserving the fence (with the next acquisition incrementing it); currently `releaseWriter` is only used by the seed helper without a postcondition assertion.

### 3. Supported staged-recovery route lacks a direct assertion

**Contract and model.** PUB-004 defines recovery outcomes and stable-key handling for committed success after lost acknowledgment; it does not impose a general orchestration policy for all uncommitted bodies ([execution.md:349–372](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/docs/spec/execution.md#L349-L372)). The finite model explicitly permits rebinding an existing `staged` key ([Publication.tla:354–366](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-7/Publication.tla#L354-L366)) and publishing the retained staged candidate under current authority without another `Execute` ([Publication.tla:392–421](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-7/Publication.tla#L392-L421)).

**Implementation.** A matching stable key returns its existing attempt, subject to same-subject identity ([index.ts:260–269](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L260-L269)); `publishAttempt` accepts staged attempts using the supplied writer authority and reads the payload, fingerprint, and provenance already stored on that attempt ([index.ts:337–378](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L337-L378)). Staging identical bytes is idempotent and conflicting bytes are rejected ([index.ts:316–334](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L316-L334)).

**Tests.** The helper re-executes the body for a known non-completed attempt ([publication.test.ts:85–100](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/publication.test.ts#L85-L100)), and the worker similarly executes before staging/publishing ([crash-worker.ts:141–151](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/harness/crash-worker.ts#L141-L151)). Existing crash coverage establishes that staged bytes are not yet a readable result ([publication.test.ts:166–179](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/publication.test.ts#L166-L179)); stale authority is rejected by publish ([publication.test.ts:253–285](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/publication.test.ts#L253-L285)). No direct assertion composes takeover, same-key/same-attempt recovery, retained candidate publication, and returned exact reference.

**Smallest follow-up.** After a staged attempt survives reopen, have a new current authority allocate/rebind the same key and assert the same attempt and generation, publish without calling the body, and verify the exact staged bytes/fingerprint/provenance and returned reference. Assert the former authority remains rejected. This covers a route already permitted by the candidate API and model; it does not select a general M3 recovery policy or claim exactly-once external work. No model or protocol change is indicated by this finding.
### 4. Insufficiently tested: exact historical reference survives reopen after supersession

**Implementation.** `readResult` selects by supplied subject and generation ([index.ts:412–435](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L412-L435)); retained snapshots are not deleted by repository operations and have restrictive ownership FKs ([185–199](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/src/index.ts#L185-L199)).

**Tests.** `exact older references remain readable after a newer result becomes current` exercises the semantic distinction but opens `:memory:` ([publication.test.ts:339–376](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/publication.test.ts#L339-L376)). File-backed reopen tests establish persistence of the old current result, not the older noncurrent reference ([104–118](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/test/publication.test.ts#L104-L118)).

**Smallest follow-up.** Make the exact-reference test file-backed, close/reopen after publishing generations 1 and 2, assert current is generation 2, and resolve generation 1 to its original payload/fingerprint/provenance. This directly composes durable retention with exact addressing.

## Model simplifications and production boundary

- The checked configurations bound one subject, two contenders, three keys, generations through 3, fences through 2, logical time through 2, and lease length 1 ([Publication.cfg:1–23](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-7/Publication.cfg#L1-L23)). TLC checks finite safety only; `CHECK_DEADLOCK FALSE` and no fairness/liveness are explicit ([README.md:27–48](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-7/README.md#L27-L48)).
- Model publication/rollback are indivisible steps; SQLite SQL statements are not interrupted individually. Payload/fingerprint/provenance are abstracted to a staged phase; clock behavior is abstracted to globally monotonic model time. These are documented limits ([execution.md:399–407](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/docs/spec/execution.md#L399-L407), [EXP-7 README:39–48](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-7/README.md#L39-L48)).
- Process kill/reopen tests prove behavior for one local SQLite file using WAL, `synchronous=FULL`, enabled foreign keys, and bounded busy timeout, not power loss, device/filesystem failure, network filesystems, distributed clocks, or multi-host operation ([node-sqlite.ts:14–24](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/experiments/exp-3/harness/node-sqlite.ts#L14-L24), [execution.md:382–387](https://github.com/mike-north/microdelta/blob/70f325a01ea898a7e8fdaa2a4f93b10929391da9/docs/spec/execution.md#L382-L387)). The prototype accepts caller-supplied `nowMs`; it does not own a production clock.
- This fixture does not implement production History and has no execution-authority record proving an author body ran before staging. The model's `bodyDone` is process-local abstraction; the fixture's repository accepts staged payload supplied by its caller.
