## 5. Five real controls

1. **Stale**: hold actual A transaction, commit B from W, read actual A; the literal oracle must accept it for its A anchor and reject it when deliberately presented as current B. No copied/main-only/immutable reader.
2. **Torn pair**: separate native autocommit metadata read B, W commit C, separate current read C; reject actual `(2,3,'C')` using the same pair oracle. Do not fabricate row JSON.
3. **IMMEDIATE reservation**: C deliberately gets writable Machine authority and BEGIN IMMEDIATE; W's fixed B commit encounters actual bounded busy/typed-busy cause. C rollback; a separately scheduled B commit succeeds. Reservation is a prohibited candidate authority/lock effect, not itself domain-row mutation. No further writable control method is reachable from R.
4. **Forbidden effects**: one coordinator-only non-SQLite 16-byte file uses exactly four full images: initial baseline, mutated main plus extra sidecar, a fresh post-recreation baseline, and the post-transient restored image. After the second image, deliberate main deletion is witnessed by an actual bounded pathname `lstat` returning ENOENT, recorded as a lifecycle observation distinct from a complete source image. Other errors or a missing observation do not prove deletion. After recreation, the transient write→restore/create→remove comparison uses the fresh inode baseline. It never compares across the deliberate replacement. Already observed sensitivity facts survive later recreation or proof-write failure. The between-barrier blindspot is expected evidence, never transient-write absence proof.
5. **False release**: C holds actual B while W commits C; use the same Q5 constraint and replacement V. C's fake end flips only its adapter claim, not native transaction. Native `.inTransaction=true` plus V's continued actual checkpoint busy must reject fake release. Only real ROLLBACK then V checkpoint/read C qualifies release; C remains alive through verification.
