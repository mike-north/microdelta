Observers are synchronous notifications (`state.report`, `notify`), not a separately supported awaited observer promise. They can request stop reentrantly; the sleeping-event and permit-handover tests exercise that trigger. Controller deadline timers escalate stop and disarm; they are control sources rather than retained domain work. Resolution “waiting” outcomes for open discovery/denial are reported semantic states, not automatically host sleeps; durable deferral sleep is the explicit host wait above.

## Finite remaining assertions

1. Priority reclaim cancellation is a distinct currently supported lifecycle with no direct named hard-stop test located in the pinned suites. Minimal discriminator: window one; member A sleeps and lends its lane; B occupies the lane; advance A's timer until A queues priority reclaim; queue C unstarted; hard stop before B releases. Assert the run settles, A never resumes/retries/publishes, C never enters body/admission/claim/send, all keep-alive timers are fired/cancelled, and A/B cannot publish late. This belongs under existing #173 CR-6.5; no new issue or production bug is warranted from static inspection.
2. Ordinary queued-lane hard stop needs its own direct two/three-member assertion; existing soft-stop queued-lane and hard-stop send-permit tests cover different states. Existing #173 already owns it.
3. Armed durable-deferral hard stop and hard-stop writer reacquisition can strengthen finite combined persisted guarantees. They reuse tested any-stop cancellation primitives and have soft-specific/end-at-observer controls, so their missing direct hard variants are weaker coverage observations, not independent suspected bugs.

No claim is made that all supported hard stops finish immediately: provider cancellation deliberately remains awaited. No test-source title is treated as stronger than its actual assertions, and no test source inventory is added to the earlier 74 executed/qualified semantic outcomes denominator.
